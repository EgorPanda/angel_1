# 10. Markdown-vault и синхронизация

Код: `app/markdown/module.py` (`MarkdownModule`, `name="markdown"`, v0.2.0).
Модуль связывает заметки приложения с обычной папкой на диске (vault),
пригодной для Obsidian и т.п.

## Основные понятия

- **Vault** — папка `.md`-файлов. Путь по умолчанию: `../vault` относительно
  `backend/` (env `ANGEL_MARKDOWN_VAULT_PATH`).
- Приоритет пути:
  1. сохранённый `module_settings.markdown.vault_path` (если непустой);
  2. иначе `core.settings.vault_path` (из `.env`).
  (`effective_vault_path` учитывает это.)
- Каждый файл имеет **id-строку** для устойчивой связи «файл ↔ запись БД»
  (ищется в markdown-фронтматере/комментарии — поиск по id в тестах
  `find_file_by_id`).

## Синхронизация

- Полная двусторонняя: изменения vault → в БД (индекс), изменения БД
  (создание/переименование/перемещение/архивация) → в файлы vault.
- Запуск: `POST /api/v1/markdown/sync` (ставит задачу `sync_markdown` в пул)
  или кнопка «Синхронизировать сейчас» в «Настройки».
  Модуль на старте (`start()`) и при событии срабатывает только
  **инкрементальная** обработка (затронутые файлы), полный `full_sync`
  — по кнопке/API/воркеру.
- Ответ: `{indexed, removed, disabled, error}`. `indexed` — создано
  или обновлено файлов, `removed` — удалено из индекса (по смене пути).
- Выполняется воркером `sync_markdown`.
- Событие `markdown:synced` публикуется в шину после завершения.

## Авто-индексация и MOC

- При `full_sync` каждая проиндексированная заметка получает
  **id-строку в frontmatter** (`id: <uuid>`), если её там ещё нет.
- Полный `full_sync` **регенерирует MOC-файлы**: для каждого индексируемого
  каталога создаётся/обновляется `<ИмяПапки>_MOC.md` со списком его
  `[[wikilink]]`-ссылок на заметки. MOC отражает текущее содержимое каталога
  и позволяет быстро перейти к любой заметке из Obsidian.
- MOC-файлы сами индексируются в таблицу `mocs` (`structure.links`).

## Архивация и удаление

- `4_Архив/Архивированные/` — папка архива (обрабатывается отдельно,
  основная синхронизация её не сканирует в общий индекс).
- Удаление заметки через сервис (`delete`) **архивирует** её: файл
  переносится в `4_Архив/Архивированные/<Заметка>-<ts>.md`, из индекса
  убирается. Для удаления из архива — повторный `delete` по пути из
  `4_Архив/Архивированные` (жёсткое удаление файла).
- `<Папка>_MOC` генерируются только для не-архивных каталогов.

## Конфигурация модуля

| Поле | Назначение |
|------|-----------|
| `vault_path` | переопределение пути vault (пустое = из `.env`) |
| `enabled` | вкл/выкл |

## Правила работы

- Не создавать файлы вручную с произвольными id — использовать синхронизацию
  (id выдаёт сервис и пишется в frontmatter).
- Пути с пробелами и кириллицей поддерживаются.
- При конфликте прав/чтения файлов — ошибка логируется (logger
  `markdown.sync`), процесс не роняет приложение.

## Результат

Владелец получает резервную копию заметок в Markdown + возможность
редактировать их внешним редактором с последующей синхронизацией обратно.
