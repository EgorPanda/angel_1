# 01. Обзор

**Angel AI** — персональный AI-ассистент для одного владельца (один основной
пользователь + присоединяемые Telegram-пользователи с ролями). Работает
локально, без облака.

## Ключевые возможности

- **Заметки** с иерархией (папки, подзаметки через parent_id), категориями,
  тегами, важностью (низкая/средняя/высокая), поиском, markdown-редактором.
- **Напоминания** (одноразовые и повторяющиеся: daily/weekly/monthly/yearly),
  планировщик их срабатывания.
- **Уведомления** с каналами (web, telegram), отметкой прочтения.
- **AI-агент**: многшаговый цикл «LLM ↔ инструменты», поддержка
  подтверждений опасных действий, провайдеры: Ollama (локально), любой
  OpenAI-совместимый HTTP, резервный провайдер.
- **Инструменты агента**: заметки (создание/поиск/редактирование/структура),
  напоминания, уведомления.
- **Telegram-бот**: принимать команды от пользователя (владелец/админ/участник).
- **Markdown-vault**: внешняя папка-хранилище, двусторонняя синхронизация.
- **Журнал активности** (activity) и **логи** (log_records), просмотр логов в
  веб-интерфейсе (раздел «Статистика») с фильтрами и контекстом перед ошибкой.
- **Веб-интерфейс** на русском языке (vanilla JS SPA, без сборщика).

## Стек

- Backend: **Python 3.14**, **FastAPI**, **SQLAlchemy 2.x (sync)**, **Alembic**.
- База данных: по умолчанию **SQLite** (`angel.db`), в проде поддерживается
  **PostgreSQL** (через `ANGEL_DATABASE_URL`).
- LLM: локальная **Ollama** (`http://localhost:11434`), OpenAI-совместимые API.
- Frontend: vanilla JS + CSS, отдаётся тем же FastAPI-приложением.
- Тесты: **pytest** (+ pytest-asyncio), FastAPI TestClient.
- Запуск одной кнопкой: `start.bat` (venv, зависимости, миграции, uvicorn).

## Основные идеи / принципы

1. **Один процесс.** Веб + бот + планировщик + пул задач живут в одном
   FastAPI-приложении. Нет микросервисов.
2. **Модульность.** Функциональность группируется в модули. Модуль описывает
   конфигурацию (ConfigField), инструменты, HTTP-роутер, подписки на события,
   lifecycle (start/stop/restart/reconfigure). Регистр модулей — `core.modules`.
3. **Конфигурация поверх .env.** У каждого модуля есть поля с дефолтами; значения
   поверх дефолтов хранятся в таблице `module_settings`. Сохранил через UI →
   перезапуск модуля применяет изменения.
4. **Ядро (Core) — единый концентратор.** Реестры и сервисы: модули, инструменты,
   разрешения, активность, конфигурация модулей, события/команды, здоровье,
   пул задач, LLM-провайдер, AI-рантайм, Telegram.
5. **AI не делает ничего без разрешений.** Каждый инструмент имеет permission и
   режим: `allow` (автоматически), `confirm` (спросить человека), `forbid`.
6. **Всё логируется.** JSON-логи в stdout + структурированные записи в БД
   (`log_records`) для просмотра в UI.
7. **Хроника как журнал.** События сохраняются в таблицу `events`, действия —
   в `activity`.

## TL;DR архитектуры

```
Web UI (SPA) ──┐
Telegram бот ──┤──> FastAPI (api/v1) ──> Core
планировщик ───┘                              │
            ┌─────────────────────────────────┐
            │ Core: modules, tools, perms,    │
            │ events, activity, config, health │
            └──────────────┬──────────────────┘
                           │
        SQLite/PostgreSQL (SQLAlchemy sync)
        Ollama / OpenAI-совместимый LLM (httpx)
        внешняя папка Markdown-vault
```

## Пользователи и роли

- Основной пользователь (`angel`, username из `ANGEL_DEFAULT_USER_USERNAME`) —
  всегда **owner**, его нельзя понизить.
- Роли: `owner` (владелец), `admin` (админ), `member` (участник).
- Права на команды бота: owner/admin.
- Неизвестный Telegram-пользователь, написавший боту, автоматически
  регистрируется с ролью `member`.
