# 09. Telegram-интеграция

Код: `app/interfaces/telegram/`. Модуль регистрируется в `main.py`
(`TelegramModule`, `name="telegram"`, version 0.2.0).

## Возможности

- Long-polling бот (`settings.telegram_poll_interval`, default 2 сек).
- Команды от пользователя; команды выполняются от имени написавшего.
- Неизвестный пользователь пишет боту → автоматически регистрируется с
  ролью `member`.
- Права команд: `owner/admin` (проверка роли).
- Дубликаты/истёкшие сообщения пропускаются.
- Health-проверка: `module:telegram` и `telegram` в `/api/v1/system/health`.

## Конфигурация (модуль `telegram`)

| Поле | Назначение |
|------|-----------|
| `token` | токен бота (из @BotFather) |
| `poll_interval` | интервал опроса, сек |
| `enabled` | bool, вкл/выкл |

Дефолты берутся из `.env` (`ANGEL_TELEGRAM_BOT_TOKEN`,
`ANGEL_TELEGRAM_POLL_INTERVAL`). Сохранение — через «Система → Модули →
telegram» (или напрямую `PUT /api/v1/system/modules/telegram/config`).
Изменения применяются после перезапуска модуля.

## Роли и команды

- `owner` — основной пользователь (`angel`), защищён от понижения.
- `admin`, `member` — Telegram-пользователи.
- Роли назначаются в веб-интерфейсе: «Система → Пользователи Telegram»
  (`POST /api/v1/system/users/{id}/role`).
- Попытка выдать роль `owner` другому пользователю отвергается (403).

## Обработка сообщений

Поток: `poll → getUpdates → для каждого update:`
1. найти/создать пользователя по `telegram_user_id` (`username` из update),
   обновить `last_seen_at`, `telegram_chat_id`;
2. проверить роль (owner/admin для исполнения команд);
3. разобрать команду → действие (создать уведомление/исполнить инструмент,
   ответить в чат);
4. безопасно ответить (внутренние ошибки логируются).

## Структура модуля

- `telegram.py`: `TelegramModule` + классы бота; `routers` (HTTP-эндпоинты,
  если нужны); регистрация как модуль ядра.
- Требует рабочую сеть до `api.telegram.org`. При недоступности DNS/сети
  логируется ошибка вида:
  `telegram poll failed: [Errno 11001] getaddrinfo failed` — бот продолжает
  опрос в следующем цикле (не является фатальной).

## Частые ошибки и как их смотреть

Любая ошибка бота попадает в `log_records` → «Статистика» → фильтр по
`module=telegram`. Ошибка `getaddrinfo failed` = нет доступа к DNS/интернету
на момент опроса. Авторизация: `telegram poll` успешно пройден → в логах
`telegram bot started`; токен должен быть валидным (не должен содержать
лишних кавычек — значения таблицы `module_settings` хранятся как JSON).
