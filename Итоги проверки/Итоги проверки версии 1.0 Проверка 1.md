## 1. Что это за приложение

**Angel AI** — персональный AI-ассистент для одного владельца. Работает локально (127.0.0.1:8000), без облака. Один процесс (FastAPI) объединяет:

- веб-интерфейс (vanilla JS SPA),
- Telegram-бот (long-polling),
- AI-рантайм (агент с инструментами),
- планировщик + пул воркеров,
- событийную шину,
- 4 доменных модуля (заметки, напоминания, уведомления, AI),
- Markdown-vault (проекция заметок в .md-файлы для Obsidian),
- логирование в БД + stdout.

## 3. Подход к разработке

### Ключевые принципы (из кода + документации)

1. **Модульный монолит** — один процесс, нет микросервисов.
2. **Модульность** — каждый модуль = класс Module с config_fields, tools, routers, event_subscriptions. Регистрация через `core.register_module()`.
3. **Конфигурация из БД поверх .env** — module_settings (БД) > .env > дефолты кода. Сохранил → перезапуск → применилось.
4. **AI через инструменты** — агент не трогает БД напрямую, только через Tool. Каждый инструмент имеет permission + default_mode.
5. **Разрешения: allow/confirm/forbid** — по умолчанию allow; опасные (delete_*, send_notification) — confirm; per-user + per-global правила в permission_rules.
6. **Всё логируется** — stdout JSON + БД (log_records) с retention 14 дней.
7. **События как хроника** — EventBus → events table + subscribers.
8. **Workers** — Scheduler тикает каждые 5с, ставит задачи в WorkerPool (concurrency=2, retry=3).
9. **Тесты** — pytest, conftest с FakeProvider, 61 тест.

### Стек

- Python 3.14, FastAPI, SQLAlchemy 2.x (sync), Alembic, SQLite/PostgreSQL
- Ollama / HTTP LLM (OpenAI-compatible), httpx
- Frontend: vanilla JS SPA, без сборщика
- Тесты: pytest + pytest-asyncio + FastAPI TestClient

### Дерево модулей

```
bootstrap_core (main.py)
├── NotesModule (notes) — 12 инструментов, CRUD + иерархия
├── RemindersModule (reminders) — 5 инструментов, расписания
├── NotificationsModule (notifications) — 2 инструмента, каналы
├── AIModule (ai) — конфигурация LLM, health
├── MarkdownModule (markdown) — vault sync, события notes → воркер
├── TelegramModule (telegram) — бот, команды, доступ
└── WorkersModuleConnector (не модуль!) — scheduler + worker pool
    ├── process_reminder → AI-напоминание / fallback
    └── sync_markdown → полная/дифференциальная синхронизация
```

### Поток данных: напоминание

```
Scheduler._scan() [каждые 5с]
  → RemindersService.due(now)
  → create_run(reminder) [idempotent по occurrence_key]
  → publish(reminder:due)
  → WorkersModuleConnector._on_reminder_triggered
  → WorkerPool.enqueue("process_reminder", {run_id})
  → _process_reminder(payload):
      ├── reminders.service.get_run/run
      ├── если LLM доступен → ai_runtime.chat(..., tool_names=["send_reminder_notification"])
      │   └── Agent.run(): LLM → tool_call send_reminder_notification → NotificationService
      └── иначе → NotificationService.send(text, "telegram", ...) [fallback]
  → update_run → "processed"
```

### Поток данных: AI-чат

```
POST /api/v1/ai/chat {text}
  → core.ai_runtime.chat(text, user_id, kind="chat")
    → Agent.run(request):
        loop (max 8 шагов):
          LLM.complete(messages, tools=схемы)
          ├── text response → parse envelope → return completed
          ├── tool_calls:
          │   для каждого:
          │     permissions.request(permission, mode)
          │     ├── allow → tool.execute() → activity.log → continue
          │     ├── confirm → create ConfirmationRecord → awaiting_confirmation
          │     └── forbid → PermissionDenied
          └── max steps → error
```

### Поток данных: заметка → vault

```
NotesService.create() → publish(NOTE_CREATED)
  → MarkdownModule._on_note_changed → WorkerPool.enqueue("sync_markdown", {action:"note", note_id})
    → MarkdownSyncService.sync_note(note_id) → .md файл с frontmatter
```

### Поток данных: Telegram

```
poll → getUpdates → _handle_update(update)
  → _remember_chat(chat_id, sender) → User (role=member если новый)
  → _resolve_sender → authorized?
  ├── нет → access_denied
  └── да → _command(text)
      ├── /start, /help → help text
      ├── /status → health snapshot
      ├── /me → user info
      ├── /note "Заголовок\nОписание" → notes.service.create()
      ├── /notes → list last 10
      ├── /remind "текст дата" → reminders.service.create()
      ├── /confirm <id> → permissions.resolve(id, approve=True)
      ├── /deny <id> → permissions.resolve(id, approve=False)
      └── свободный текст → ai_runtime.chat(text, tool_names=None)
```

## 7. Задумка и идея

Проект задуман как **персональный AI-компаньон** для одного человека:

- **Владелец** (owner, username=angel) — единственный админ, не может быть понижен.
- **Telegram-пользователи** — присоединяются по chat_id, получают роль member; admin может быть выдан владельцем.
- **AI-агент** — может создавать заметки, напоминания, отправлять уведомления, но только с разрешений (allow/confirm/forbid).
- **Markdown-vault** — резервная копия + редактирование внешним редактором.
- **Настройки** — модульные, через UI, без перезапуска приложения (кроме модуля AI).
- **Логи** — полный аудит в БД с контекстом (correlation_id, request_id, task_id, user_id).

### Расхождения / замечания
1. **docs/implementation-plan.md** говорит 58 тестов — устарело (сейчас 61).
2. **11-api.md** описывает системные пути как /system/*, но на самом деле /api/v1/system/* — упрощение.
3. **WorkersModuleConnector** — не модуль, а коннектор, установленный в bootstrap. Документация это уточняет, но может ввести в заблуждение.
4. **MarkdownModule** — зависит от notes (через events), но в `on_register` подписывается на события notes, что работает только если notes уже зарегистрирован (а он зарегистрирован раньше в bootstrap — OK).
5. **Telegram-бот** не перезапускается при смене токена в UI — нужно явно перезапускать модуль.
6. **Планировщик** тикает каждые 5с — для production может быть много; настраивается через `ANGEL_SCHEDULER_INTERVAL`.
7. **WorkerPool** — concurrency=2 по умолчанию; для интенсивной нагрузки мало.
8. **AI-агент** при max_steps=8 может делать много LLM-вызовов за один chat — нет лимита по времени.
9. **FallbackProvider** — при ошибке основного провайдера пробует fallback; но timeout основного = 60с, что долго.
10. **Confirmation TTL=300с** — 5 минут; для интерактивного использования достаточно, но для Telegram-бота может быть мало.
11. **Логи** — retention 14 дней, автоочистка каждые 256 записей; для активного использования может быть мало.
12. **CORS** — по умолчанию localhost:5173 (Vite); для других фронтенд-хостов нужно менять ANGEL_CORS_ORIGINS.
13. **Дашборд** — `users: 1` захардкожено (main.py:22).
14. **Markdown sync** — при старте markdown-модуля делает полную синхронизацию (start → _run_full_sync); может быть тяжело для большого vault.
15. **Telegram polling** — offset managed в памяти; при перезапуске бота повторно обработает последние обновления (дубликаты пропускаются через processed count).
16. **Парсинг даты напоминания в Telegram-боте** — поддерживает HH:MM, YYYY-MM-DD, YYYY-MM-DDTHH:MM, DD.MM.YYYY HH:MM; но без года берёт текущий год.
17. **Обработка ошибок LLM** — в agent.py: ошибки LLM ловятся, ставят статус error; другие исключения — тоже error с возвратом текста.
18. **Идентификатор пользователя** — `core.user_id()` всегда возвращает основного пользователя; для Telegram-команд user_id передаётся из контекста Telegram-пользователя.

### Потенциальные улучшения
1. **Аутентификация** — сейчас нет паролей/токенов для веб-интерфейса; только локальный доступ.
2. **Rate limiting** — нет лимитов на API-запросы.
3. **Webhooks для Telegram** — вместо polling (актуально для продакшена).
4. **Батчинг уведомлений** — сейчас каждое напоминание = отдельное уведомление.
5. **Индексация** — полнотекстовый поиск по заметкам (сейчас LIKE-поиск).
6. **UI подтверждений** — в веб-интерфее нет страницы подтверждений (есть только через Telegram /confirm).
7. **Экспорт заметок** — нет массового экспорта/импорта.
8. **Версионирование заметок** — нет истории изменений.
9. **Расширенные роли** — только owner/admin/member; нет гранулярных разрешений на модули.
10. **Мониторинг** — health-check только в памяти; нет внешнего мониторинга (ping/heartbeat).
